# UI 设计与验收规范

本规范记录已确认的桌面界面基线，约束后续视觉和交互修改。流程见 [开发与交付流程](workflow.md)，模块职责见 [架构说明](architecture.md)。

## 预览与实施

- 涉及视觉或交互的调整，先提供用户可手动批注的浏览器预览，确认后再写入桌面程序；静态图片不能替代这个确认环节。
- 已批准的预览与批注是实施依据。记录批准版本及修改点；不要通过修改预览来迁就偏离设计的实现。
- 本地历史预览位于 `artifacts/typography-preview/index.html`，属于忽略文件，新克隆可能没有。端口和截图路径不作为永久设计来源；缺失时依据本文恢复预览，新设计仍需确认。
- Qt 与浏览器的字体、盒模型不同，必须对比实际渲染，不能仅凭相同 CSS/QSS 数字宣称一致。平台导致的必要差异应明确说明。

## 文字层级

尺寸使用逻辑像素，随系统缩放显示。默认字体为 `Microsoft YaHei UI`，正文保持常规字重。

| 用途 | 字号 | 字重与颜色 |
| --- | --- | --- |
| 顶部“批量改名” | 21px | 700，主文字色 |
| “改名规则” | 16px | 700，主文字色 |
| “文件预览” | 15px | 700，主文字色 |
| 查找替换、前后缀、自动编号分组 | 14px | 实际粗体，`#36445A` |
| 输入内容、字段标签、顶部副标题 | 14px | 常规；辅助文字使用弱化颜色 |
| 说明、计数、“命名预览”标签 | 13px | 常规，`#626D7D` |

`HeadingLabel` 负责标题粗体字形，`theme.py` 定义层级。网页分组的 600 字重与桌面的粗体映射以实际显示为准。Windows 当前使用 DirectWrite；字体引擎在 QApplication 创建前配置。修改字体时检查真实字形，防止样式标为粗体却显示常规字形，或重新出现颗粒感。

| 元素 | 基线 |

| 窗口背景 / 面板背景 | `#F7F9FC` / 白色 |
| 主文字 / 主操作色 | `#17243B` / `#2864F5` |
| 面板边框 / 圆角 | `#E1E7F0`，1px / 10px |
| 规则输入框 | 外部高度约 36px，圆角 6px，水平内边距 10px |
| 输入边框 / 焦点边框 | `#D8E0EC` / `#3867ED` |

主操作、次操作和禁用状态应清晰区分。“填入查找”保留可见按钮边框；不能退化为难以辨识的纯文字。文本输入及可选取文字区域使用 I 形鼠标指针，保留键盘焦点提示和中文可访问名称。

## 布局与缩放

- 保持左侧规则、右侧文件预览、底部操作区的结构。常规侧栏宽 306px，窗口宽度不超过 830px 时为 280px，并隐藏顶部副标题。
- 侧栏左右内边距 16px；字段标签宽 44px、字段间隔 10px；分组分隔线上方留 16px、下方留 12px；编号展开内容顶部留 16px。
- 规则与命名预览在同一滚动内容中。小窗口允许滚动，不用固定预览面板或渐隐遮罩盖住自动编号、文字和输入控件。
- 初始窗口适配屏幕可用区域，最大目标尺寸为 1100×700；桌面最小尺寸为 760×420。网页的窄屏单列展示不代表桌面也要改成单列。
- 表格显示原文件名、新文件名、状态；长内容使用省略显示并可悬停查看完整信息，不能直接切掉字形。

## 必须保留的交互

- 文件名文本框只读且可选取，排除最后一个扩展名；“填入查找”只使用选中的部分文字。点击按钮失焦后保留选区；没有选区时提示选取，不覆盖已有查找内容。
- 文件列表支持复制原文件名、多选及逐行复制；列表中的完整文件名仍包含扩展名。
- 开关与编号展开保持平滑；快速反复切换后布局正确，隐藏控件不截获操作。动画不能妨碍输入或改变命名结果。
- 确认框使用具体操作名称，默认按钮和 Escape 均为取消；操作期间正确禁用冲突操作，保留撤销和恢复入口。

## 视觉验收清单

- 使用相同示例、选中行和规则状态对照预览与实际程序，按可比的逻辑尺寸和系统缩放检查，避免把 2 倍截图直接当作尺寸差异。
- 检查常规窗口（1100×700）和小窗口（810×488），确认标题、输入、分隔线、按钮及底部操作区没有遮挡或生硬裁切。
- 覆盖空列表、长文件名、部分文字选区、编号开关及展开、禁用按钮、错误状态和确认弹窗。
- 改动字体或屏幕适配时，核对目标屏幕缩放下的清晰度和字重；无法验证的缩放明确记录。
- 按工作流程运行相关测试并检查实际 EXE。测试通过不能代替视觉验收；未经用户确认，不另行改变已批准的审美方向。
